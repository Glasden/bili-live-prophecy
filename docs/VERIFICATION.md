# 实现与验证说明

## 1.0.0 的代码来源

1.0.0 基于已完成浏览器验证的 0.4.0 发布整理，改动仅为 7 处版本标识及脚本头部的仓库、反馈、安装和更新 URL。忽略这些改动后，完整脚本与 0.4.0 字节内容一致。参与逻辑、设置格式、消息通道与防重复记录前缀保持不变。

脚本是单文件源代码，无需构建。`tests/` 中的两组 Node 测试直接加载该发布文件，包括最后一项隔离 VM 检查；仓库不保留另一份可能失配的策略副本。

## 实现分工

- 直播间父页负责入口、设置、浮窗定位和全屏切换。
- 官方预言 H5 负责 SDK、登录和接口编码。精简模式显示脚本自己的参与卡片；完整模式恢复官方页面。
- 手动操作先记录选择意图，再显示确认框；提交前重新核对账户、题目状态、费用与余额。
- 自动模式默认关闭，在最后 5 秒检查预算、账户绑定、手动意图和参与记录，通过后才提交；失败或结果不明时不自动重试。
- 浮窗进入全屏容器时使用保持节点状态的 `moveBefore`，避免正常全屏切换重载 iframe。对于页面直接调用视频 `requestFullscreen()` 的情况，将同次请求交给现有父容器。
- 若播放器实际删除了包含 iframe 的整个 DOM 子树，只能重新载入子页；持久化的操作记录继续用于防重复。

全屏节点迁移依据：[Chrome 的 moveBefore 说明](https://developer.chrome.com/blog/movebefore-api)、[WHATWG Fullscreen](https://fullscreen.spec.whatwg.org/)。官方页面入口为 `https://live.bilibili.com/p/html/live-app-guessing-game/index.html`，参数由当前直播间的公开房间信息生成。

### 0.4.0 浏览器基线

Edge **155.0.4283.45**，原始官方 H5 / 静态 JavaScript，加上模拟视频、账户、时间与 API；**15 项场景全部通过**：

1. 下方居中的精简卡片、完整面板往返。
2. 手动取消及确认参与。
3. 多道开放预言切换。
4. 确认期间截止时阻止提交。
5. 播放器容器全屏。
6. 页面直接请求视频全屏、全屏确认参与。
7. 全屏中收起并重新展开、工具栏不触发播放器点击。
8. 进入全屏后出现新预言。
9. CSS 网页全屏。
10. 视频尺寸短暂不可用后的恢复。
11. 开放 ShadowRoot 内的视频。
12. ShadowRoot 内直接请求视频全屏。
13. 旧版已保存的自动设置继续生效。
14. 手动取消抑制该题自动参与。
15. 390px 窄窗口的卡片与确认按钮。

测试通过 Playwright 发送的可信鼠标事件（`isTrusted=true`）调用 **实际 Fullscreen API**；正常进出全屏保持 iframe 文档标识。3 次参与 POST 全由模拟后端处理，真实 API 请求与真实参与 POST 均为 **0**。上述 15 项是 0.4.0 的浏览器基线，本次 1.0.0 发布没有将其描述为重新运行的一套集成测试。

## 验证边界

浏览器开发验证直接注入 userscript，没有安装真实 Tampermonkey 扩展，也没有接入已登录的真实直播播放器。用户曾报告前期版本真实手动参与成功；这不等同于 1.0.0 自动参与的实网验证。

浏览器自带媒体菜单绕过网页 API 的原生全屏、跨文档播放器 iframe 全屏和关闭的 Shadow DOM 尚未验证。功能依赖官方页面及现代浏览器能力，平台前端变动后可能需要适配。

开发与截图均不包含真实凭证；本仓库不包含官方静态 JavaScript 的完整副本，也不包含个人远控环境、设备信息或浏览器配置。
